# M6 — `examples/react-spa/` (Vite + React + TS)

Egy futtatható, minimális React SPA, ami a backendet a *teljes* auth-szerződés szerint használja: in-memory access token + HttpOnly refresh cookie + CSRF double-submit, 401 → `/refresh` → retry, opcionális 2FA TOTP.

## Cél

A projekten dolgozó frontend csapat ne kelljen, hogy a docs/auth/* alapján rakjon össze egy működő példát. Egy `npm install && npm run dev`-kor elindul a Vite, a backend dev-szervert proxy-zza, és a login → profile flow azonnal végigjárható.

## Design-döntések

- **In-memory access token, nem `localStorage`**. A `setSession(token, csrf)` egy modul-level closure-be teszi; page-reload törli, és a `__Host-refresh` cookie alapján az `AuthContext` mount-kor lefuttat egy `/me` round-tripet — ami 401-re kényszeríti a fetch-klienst egy `/refresh`-re, és újratöltődik a session. Így a tab-zárásig perzisztált session megvan, de XSS-vel exfiltrálni nem lehet.
- **Coalesced refresh**. Több párhuzamos 401 csak *egyetlen* `/refresh` POST-ot vált ki — a `refreshing: Promise<boolean> | null` modul-szintű "lock" gondoskodik róla.
- **CSRF double-submit**. A `/refresh` POST-on az `X-CSRF-Token` headert a `csrf_token` cookie értékéből olvassuk vissza (a backend ezt nem `HttpOnly`-ként küldi, mert JS-nek kell). Ha a cookie nem érhető el (külön origin + tab korai életszakasza), fallback: a memóriában tárolt utolsó CSRF érték.
- **`ProtectedRoute` placeholder + nem redirect**. Amíg az induló `/me` round-trip fut, "Checking session…" jelenik meg — egy azonnali `/login`-redirect a valid refresh-cookie ellenére flash-elne.
- **`react-router-dom@6`, nem TanStack Router**. A példa célja a *baseline* — a router-data layer vagy a query cache (TanStack Query / SWR) opcionálisan utólag csatolható, az auth-shape nem változik tőle.

## Futtatás

```bash
cd examples/react-spa
cp .env.example .env
npm install
npm run dev          # http://localhost:5173
```

Két dev mód:

| Mód | `VITE_API_BASE` | Cookie viselkedés | CORS config |
|---|---|---|---|
| Same-origin (alapért.) | üresen hagyva | `__Host-` cookie megy | nem kell |
| Separate-origin | pl. `http://localhost:8080` | HTTPS + Secure kell `__Host-`-hoz, dev-ben drop a prefix | `src/config/cors.php` + `credentials: true` |

A `vite.config.ts` a `/api/v1/*` requesteket az `APP_BACKEND_ORIGIN` (default `http://localhost:8080`) felé proxyzza, így same-origin dev-ben a böngésző egyetlen origin-t lát.

## Verifikáció

- **`npm run build`** zöld (Vite + `tsc -b`), 41 module, ~171 kB unminified bundle (~56 kB gzip).
- **`npm run typecheck`** zöld — `strict: true`, `noUnusedLocals/Params`, `noUncheckedIndexedAccess` mind aktív.
- **Backend kompatibilitás**: a használt endpointok (`/api/v1/auth/login`, `/2fa/verify`, `/refresh`, `/logout`, `/me`) mind léteznek az M2.b/M2.c PR-ekből, a CSRF/Bearer szerződés az `AuthController` 2026-05-25 állapotát követi.

## Mit *nem* tartalmaz ez a PR

- **Router data layer** (loaders, action mutations) — sima react-router-dom routes maradnak.
- **Query cache** (TanStack Query / SWR) — a `/me` direktben az `AuthContext`-ben fut, ami a demóhoz elég.
- **Styling**: csak inline stílusok. CSS framework (Tailwind, vanilla-extract) nincs.
- **Error boundary**, **i18n**, **toast notifications** — utólag csatolható.
- **Token rotation observability** — a `/refresh` válaszára csak a token + csrf cserélődik, az `expires_in`-t nem használjuk timer-alapú pro-active refresh-re. Az M6.b ezt hozhatja.
