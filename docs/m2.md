# M2.a — Kulcsgen + TokenService + refresh_tokens tábla

**Cél**: a JWT auth alapinfrastruktúrája — RS256 kulcspár generátor (`bin/console keys:generate`), `TokenService` (access issue + verify, refresh issue + rotation + reuse detection), `refresh_tokens` tábla és PDO repository. **Még nincs middleware vagy endpoint** — azt M2.b szállítja.

## Új fájlok

### Auth réteg
- [src/Framework/Auth/TokenService.php](../src/Framework/Auth/TokenService.php) — `issueAccessToken`, `verifyAccess`, `issueRefreshToken`, `rotateRefresh`, `revokeRefresh`. Reuse detection: ha egy revokált refresh-t újra próbálnak, a teljes `family_id` revokálódik.
- [src/Framework/Auth/RefreshTokenRepository.php](../src/Framework/Auth/RefreshTokenRepository.php) — PDO CRUD a `refresh_tokens` táblán. Prepared statementek, sqlite/postgres/mariadb-kompatibilis SQL.
- [src/Framework/Auth/JwtConfigFactory.php](../src/Framework/Auth/JwtConfigFactory.php) — `Lcobucci\JWT\Configuration` builder, RS256-ra korlátozva. Inline PEM (env) vagy fájl-elérési út.
- [src/Framework/Auth/SystemClock.php](../src/Framework/Auth/SystemClock.php) — triviális PSR-20 óra impl (`Psr\Clock\ClockInterface`).

### Console
- [src/bin/console](../src/bin/console) — CLI entry point (executable).
- [src/Framework/Console/Command.php](../src/Framework/Console/Command.php) — parancs interfész.
- [src/Framework/Console/Application.php](../src/Framework/Console/Application.php) — parancs-regiszter + dispatcher + help.
- [src/Framework/Console/KeysGenerateCommand.php](../src/Framework/Console/KeysGenerateCommand.php) — `keys:generate [--bits=4096] [--out=…] [--force]`. RSA kulcspár (default 4096 bit), `var/keys/jwt-{private,public}.pem`, file mode 0600/0644.

### Config + migration
- [src/config/jwt.php](../src/config/jwt.php) — algorithm (RS256 fix), issuer, audience, access_ttl (900s), refresh_ttl (2592000s), clock_skew (5s), kulcs forrás (env inline vagy path).
- [db/migrations/postgresql/001_create_refresh_tokens.sql](../db/migrations/postgresql/001_create_refresh_tokens.sql) — PostgreSQL séma.
- [db/migrations/mariadb/001_create_refresh_tokens.sql](../db/migrations/mariadb/001_create_refresh_tokens.sql) — MariaDB/MySQL séma. (Doctrine/migrations M4.a-ban érkezik.)

### Tesztek
- [src/tests/Framework/Auth/TokenServiceTest.php](../src/tests/Framework/Auth/TokenServiceTest.php) — 10 teszt: issue/verify roundtrip, lejárat, malformed, rotation, family-id stabilitás, **reuse detection**, wrong-user reject, unknown reject, expired refresh reject, revoke idempotencia. Determinisztikus `FrozenClock` + on-the-fly RSA 2048 keypair.
- [src/tests/Framework/Auth/RefreshTokenRepositoryTest.php](../src/tests/Framework/Auth/RefreshTokenRepositoryTest.php) — 6 teszt: store/find, missing, markRotated idempotencia, revokeFamily csak aktív sorokat érint, purgeExpired. sqlite in-memory.
- [src/tests/Framework/Auth/JwtConfigFactoryTest.php](../src/tests/Framework/Auth/JwtConfigFactoryTest.php) — 4 teszt: inline + path kulcs, algoritmus reject, hiányzó kulcs reject.

## Módosítások

- [src/composer.json](../src/composer.json) — `lcobucci/jwt: ^5.3`, `psr/clock: ^1.0`.
- [src/Framework/Dal.php](../src/Framework/Dal.php) — `public static getConnection(): PDO` proxy a meglévő `protected static connection()` fölé. Nem érinti a meglévő subclass-okat.

- **PHPStan level 1**: 20 hiba (volt 21, csökkent eggyel); **0 új hiba** az új `Framework/Auth/*` és `Framework/Console/*` osztályokból.

- **`gitnexus_detect_changes`**: 3 fájl / 2 szimbólum (`Dal`, `Dal::connection`); risk=high a Dal downstream-en futó processek miatt (DB-t használó kontrollerek), de a `connection()` metódus **nincs módosítva** — csak egy új proxy került mellé.

## Biztonsági jegyzetek

- Az access token claim-jeiben **NINCS PII** (csak `sub` = userId, `roles`, `iat`, `exp`, `iss`, `aud`, `jti`).
- A refresh token a kliensnél **plain string**; szerveren csak `SHA-256(token)` hash tárolódik. Token lopás esetén a támadó nem tudja a hashből visszafejteni az értéket.
- A `family_id` (UUID) köt össze egy login-szekcióhoz tartozó összes rotált refresh tokent. Reuse detection: ha egy revokált tokent használnak, az egész család revokálódik.
- A private key fájl mode kötelezően `0600`. A `keys:generate` `--force` nélkül soha nem ír felül meglévő kulcsot.

# M2.b — AuthMiddleware + `#[RequireAuth]` + auth endpointok

**Cél**: a Bearer-alapú auth flow összerakása az M2.a infrastrukturájára. PSR-15 middleware ami nem reject-el (csak felismer); attribútum-alapú policy a Dispatcherben; négy endpoint a `/api/v1/auth/*` alatt.

## Új fájlok

### Auth réteg
- [src/Framework/Auth/AuthenticatedUser.php](../src/Framework/Auth/AuthenticatedUser.php) — immutable value object: `id`, `roles`, `jti`. `hasRole()` és `hasAnyRole()`. NEM azonos a `Models\User`-rel, csak a token claim-jeit hordozza.
- [src/Framework/Auth/RequireAuth.php](../src/Framework/Auth/RequireAuth.php) — method / class attribute.
- [src/Framework/Auth/RequireRole.php](../src/Framework/Auth/RequireRole.php) — repeatable attribute, variadic role string lista.
- [src/Framework/Auth/AuthMiddleware.php](../src/Framework/Auth/AuthMiddleware.php) — PSR-15: parsing → verify → set `user` attribute. Hibák esetén **nem** dob; `unauthenticated_reason` attribútumba ír. A Dispatcher dolga eldönteni, hogy az adott endpoint kötelezi-e az autentikáltságot.

### Endpointok
- [src/Framework/Controllers/Api/V1/AuthController.php](../src/Framework/Controllers/Api/V1/AuthController.php) — `POST /login`, `POST /refresh` (double-submit CSRF), `POST /logout`, `GET /me` (RequireAuth). Cookie nevek: `__Host-refresh` (httpOnly Secure SameSite=Strict, path=`/api/v1/auth`) és `csrf_token` (JS-olvasható, path=`/`).

### Tesztek
- [src/tests/Framework/Auth/AuthMiddlewareTest.php](../src/tests/Framework/Auth/AuthMiddlewareTest.php) — 4 teszt: pass-through, valid bearer, malformed header, invalid token (reason rögzítés).
- [src/tests/Framework/Auth/RequireAuthIntegrationTest.php](../src/tests/Framework/Auth/RequireAuthIntegrationTest.php) — 7 teszt: `#[RequireAuth]` accept/reject, fallback reason, `#[RequireRole]` egyetlen / több / hiányzó role, 401-precedes-403.

## Módosítások

- [src/Framework/Bootstrap.php](../src/Framework/Bootstrap.php) — pipeline most: `ErrorHandler → Cors → Auth → LegacyDispatcher`. A `TokenService` és `AuthMiddleware` try/catch-ben épül: ha hiányzik a JWT kulcs (még nem futott a `keys:generate`), az auth middleware nem regisztrálódik, a `#[RequireAuth]` kontrollerek 401-et dobnak — graceful degradation.
- [src/Framework/Request.php](../src/Framework/Request.php) — két új public property: `?AuthenticatedUser $authUser`, `?string $unauthenticatedReason`. A `HttpAdapter` tölti.
- [src/Framework/Http/HttpAdapter.php](../src/Framework/Http/HttpAdapter.php) — PSR-7 `user` és `unauthenticated_reason` attribútumokat átteszi a legacy Request-re.
- [src/Framework/Dispatcher.php](../src/Framework/Dispatcher.php):
  1. **CSRF skip `/api/v1/*` alatt** — Bearer token önmagában CSRF-mute. A `/api/v1/auth/refresh` a double-submit cookie-jával gondoskodik magáról.
  2. `processAnnotation` új ágak: `RequireAuth` → 401 ha nincs `authUser`; `RequireRole` → előbb 401-et próbál, csak utána 403-at.
  3. A `processAnnotation` szignaúrája bővült `Request $request`-tel.

## Verifikáció

- **PHPUnit**: 63/63 zöld (52 → 63, +11 új teszt).
- **PHPStan level 1**: 20 hiba — változatlan. 0 új hiba az új kódból.
- **`gitnexus_detect_changes`**: 5 fájl / 15 szimbólum; risk=medium; 1 affected process (HandleRequest). A `crossSiteRequestForgeryProtection` és `processAnnotation` érintettsége várt.

## Endpoint összefoglaló

| Method | URL | Body / Cookie | Auth | Válasz |
|---|---|---|---|---|
| `POST` | `/api/v1/auth/login` | `{email, password}` | nyilvános | `{access_token, expires_in, csrf_token, user}` + Set-Cookie refresh + csrf |
| `POST` | `/api/v1/auth/refresh` | refresh cookie + `X-Csrf-Token` header | double-submit | új `{access_token, expires_in, csrf_token}` + rotated cookies |
| `POST` | `/api/v1/auth/logout` | refresh cookie | nyilvános | `{ok: true}` + cookie clear |
| `GET` | `/api/v1/auth/me` | — | `Authorization: Bearer …` | `{id, email, username, roles}` |

## Biztonsági jegyzetek

- Az `AuthMiddleware` **soha nem reject-el**, csak rögzít. Így a nyilvános endpointok (`/api/v1/example/public`) is működnek, miközben a `#[RequireAuth]`-os endpointok 401-et adnak.
- A refresh endpoint **double-submit CSRF**-et követel: a `csrf_token` cookie és az `X-Csrf-Token` header `hash_equals()`-szel egyezni kell. A Same-Origin Policy garantálja, hogy a támadó nem tudja egyszerre olvasni a cookie-t és beállítani a headert.
- A `__Host-` prefix kötelez: `Secure`, `Path=/`, **nincs** `Domain` attribute. Local dev-ben (`APP_ENV=local`) a `Secure` flag automatikusan kikerül a cookie-ból (HTTP).
- A refresh cookie `Path=/api/v1/auth` — csak az auth endpointokra megy, nem szivárog egyéb requestbe.
- A `2FA` flow még **nincs** itt — az M2.c PR-ben dispatches a login alagútja a challenge endpointra.
