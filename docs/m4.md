# M4 — Adatréteg, validáció, OpenAPI

## M4.a — doctrine/migrations + Repository réteg

**Cél**: hivatalossá tenni a séma-management-et a `doctrine/migrations` könyvtárral (a M2.a-ben kézzel írt SQL helyett), és bevezetni egy PDO-injektált Repository réteget a `Models\AbstractUser` és `Models\TwoFactorModel` static finder metódusai helyett. Az M4.a additív: a régi static finder API változatlanul működik, az új repositorykat új kódból érdemes használni.

## Új fájlok

### Migrations infrastruktúra
- [src/migrations.php](../src/migrations.php) — `doctrine/migrations` konfig (`migrations_paths` → `db/migrations/`, `Db\\Migrations` namespace, `all_or_nothing=true`, `transactional=true`).
- [src/migrations-db.php](../src/migrations-db.php) — DB-kapcsolat env változókból (`DATABASE`, `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD`). Driver-választás `pdo_mysql` vagy `pdo_pgsql` a `DATABASE` env alapján.

### 4 migration osztály
- [db/migrations/Version20260525_010000_CreateUserTable.php](../db/migrations/Version20260525_010000_CreateUserTable.php) — `user` tábla (uuid, username, firstname, lastname, email, password_hash, activation_hash, is_active, password reset, created_at/updated_at) + 5 unique index.

- [db/migrations/Version20260525_010300_CreateRefreshTokens.php](../db/migrations/Version20260525_010300_CreateRefreshTokens.php) — a M2.a kézzel írt sémájának platform-független doctrine-megfelelője.

### Repository réteg

## CLI használat

```bash
# Status (függő migrációk listája)
vendor/bin/doctrine-migrations migrations:status

# Apply all pending
vendor/bin/doctrine-migrations migrations:migrate

# Rollback to specific version
vendor/bin/doctrine-migrations migrations:execute "Db\Migrations\Version20260525_010000_CreateUserTable" --down

# Generate skeleton for a new migration
vendor/bin/doctrine-migrations migrations:generate
```

A `migrations.php` és `migrations-db.php` automatikusan beolvasódik (a `src/` mappából futtatva). Env változók: ld. `src/.env.example`.

## Mit *nem* tartalmaz ez a PR

- **AuthController repositorykra átállás** — még a static finder metódusokat (`User::findByID`, `TwoFactorModel::findByUserIdAndMethod`) használja, mert constructor-injection a controllerekhez M3.d follow-up. Amint az landol, az AuthController automatikusan kapja a `UserRepository` és `TwoFactorRepository` példányokat.
- **`AbstractUser` static finder eltávolítása** — egyelőre marad, mert a `Auth.php`/`View` legacy code még hivatkozhat rá. Egy követő PR (Auth.php deprecate) fogja törölni.
- **`TwoFactorModel` entity-hydratálás** — a `TwoFactorRepository` jelenleg array-rekordokkal dolgozik; ha entity-példányokra van szükség (pl. service-layer minta), a repositoryban kiterjeszthető.

## Migrációs jegyzet (production deploy)

```bash
composer install --no-dev --optimize-autoloader
APP_DI_COMPILE=1 php -r "require 'vendor/autoload.php'; Framework\ContainerFactory::build('var/cache/di');"
vendor/bin/doctrine-migrations migrations:migrate --no-interaction
bin/console route:cache
```

Aki már M2.a-s kézzel írt SQL-lel létrehozta a `refresh_tokens` táblát, a `doctrine_migration_versions` meta-tábla nélkül indul. Ekkor:
```bash
vendor/bin/doctrine-migrations migrations:sync-metadata-storage --no-interaction
vendor/bin/doctrine-migrations migrations:version "Db\Migrations\Version20260525_010300_CreateRefreshTokens" --add --no-interaction
```

Ez „létezőnek" jelöli az M2.a séma-állapotot anélkül, hogy ténylegesen újra futtatná. A többi (`user`, `role`, `two_factor`) tábla már létezik a `docker/mariadb/init.sql`-ből, ami szintén kézi setup — ugyanígy `--add`-dal kell jelölni mindegyiket.

A teljes migrációs táblázat:

| Migration | Adja |

| `Version20260525_010200_CreateTwoFactorTable` | `two_factor` (TOTP/email enrollment per-user, unique (user, method)) |

## M4.b.1 — Request DTO-k + symfony/validator

**Cél**: a kontroller akciók kapjanak strukturált, validált bemenetet `array` helyett. A bejövő JSON-t a `Dispatcher` automatikusan hidratálja a `Validatable` DTO-kba, és a `symfony/validator` futtatja a property-szintű kényszereket. Hibás kérés → **422 Unprocessable Entity** RFC 7807 problem+json-nal, az új `errors` mezőben field → list<string> map-pel.

### Új fájlok

#### Validation infrastruktúra
- [src/Framework/Validation/Validatable.php](../src/Framework/Validation/Validatable.php) — üres marker interfész. Ennek a megléte jelzi a `Dispatcher`-nek, hogy az adott controller-paraméter a request body-ból hidratálandó.
- [src/Framework/Validation/ValidationException.php](../src/Framework/Validation/ValidationException.php) — `RuntimeException` fix `code=422` kóddal és `getErrors(): array<string, list<string>>` getterrel. Az `ErrorHandlerMiddleware` ezt látja, és a `errors` mezőt rakja a problem+json-be.
- [src/Framework/Validation/RequestHydrator.php](../src/Framework/Validation/RequestHydrator.php) — konstruktor-driven hidratátor:
  1. A DTO konstruktor-paramétereit reflectionnel olvassa.
  2. Minden paraméterhez megnézi, van-e a payloadban azonos kulcs.
  3. Típusellenőrzés (`string`/`int`/`float`/`bool`/`array`/class) — eltérés → mezőszintű "type" hiba.
  4. Hiányzó kulcs + default → default; hiányzó + nullable → null; egyébként "required" hiba.
  5. Hidratálás után a `symfony/validator` futtatja az `Assert\\*` attribútumokat.
  6. Bármilyen hiba → `ValidationException` aggregált errors map-pel.

#### DTO-k
- [src/Application/Dto/LoginRequest.php](../src/Application/Dto/LoginRequest.php) — `email` (`NotBlank`, `Email`, max 254) + `password` (`NotBlank`, max 255). Readonly konstruktor-promotált prop-ok.
- [src/Application/Dto/VerifyTwoFactorRequest.php](../src/Application/Dto/VerifyTwoFactorRequest.php) — `challenge_token` (`NotBlank`) + `code` (`NotBlank`, length 4–10).

### Módosítások

- [src/composer.json](../src/composer.json) + composer.lock — új dep `symfony/validator: ^7.1` (tranzitív: `symfony/polyfill-php83`, `symfony/translation-contracts`).
- [src/Framework/Dispatcher.php](../src/Framework/Dispatcher.php) — `handleRequest` végén a kontroller-hívás új `resolveActionArgs()` privát metóduson keresztül megy:
  1. Ha a paraméter típusa `Validatable` leszármazott → `container.get(RequestHydrator::class)->hydrate(...)` a `$request->getJson()`-ból.
  2. Egyébként ha a paraméter neve egyezik egy route-paraméterrel → route érték.
  3. Legacy fallback (egyparaméteres untyped akció + non-GET) → `$_POST` változatlanul.
  4. Egyébként default vagy nullable → null.

  A korábbi `if ($method->getNumberOfParameters() === 1)` heurisztika kiváltva — minden meglévő action továbbra is működik (mind 0 paraméterű, kivéve a két átírt login/verifyTwoFactor).
- [src/Framework/Http/ErrorHandlerMiddleware.php](../src/Framework/Http/ErrorHandlerMiddleware.php) — a `problemResponse()` payload-jába kerül `errors` mező, ha a Throwable `ValidationException`.
- [src/Framework/Controllers/Api/V1/AuthController.php](../src/Framework/Controllers/Api/V1/AuthController.php) — `login(LoginRequest $body)` és `verifyTwoFactor(VerifyTwoFactorRequest $body)`. A kézi `getJson()` + null-coalesce + 400-ow hibalogika törölve — a `Dispatcher` hidratátora elvégzi.

### Új tesztek
- [src/tests/Framework/Validation/RequestHydratorTest.php](../src/tests/Framework/Validation/RequestHydratorTest.php) — 9 teszt: happy-path hidrat, kötelező mező, email format, típuseltérés, length min, nem-`Validatable` cél, extra kulcsok, multi-constraint mezőre, default érték.
- [src/tests/Framework/Validation/ValidationExceptionTest.php](../src/tests/Framework/Validation/ValidationExceptionTest.php) — 2 teszt: errors + code, custom message.
- [src/tests/Framework/Http/ErrorHandlerMiddlewareTest.php](../src/tests/Framework/Http/ErrorHandlerMiddlewareTest.php) — +1 teszt: `ValidationException` → 422 + `errors` mező.

### Verifikáció

- **PHPUnit**: 108 → **120/120 zöld** (+12 új teszt: 9 hydrator + 2 exception + 1 errorhandler 422).
- **PHPStan level 1**: **14 hiba** — változatlan; 0 új a `Validation/`, `Dto/`, módosított `Dispatcher`/`ErrorHandlerMiddleware`/`AuthController` területekről.
- **`gitnexus_detect_changes`**: 6 fájl, 15 érintett symbol (mind szándékos: login/verifyTwoFactor signature-csere, Dispatcher resolver, ErrorHandler errors mező). Az érintett processek (`Login → Response`, `VerifyTwoFactor → Response`, `HandleRequest → …`) változatlan tesztekkel mennek tovább, csak az 1-es lépés (entry symbol) változott.

### Mit *nem* tartalmaz ez a PR

- **Egyéb endpoint DTO-átállása** — csak a `login` + `verifyTwoFactor` lett átkötve. A `refresh` és `logout` cookie+CSRF alapú, body nem kell; a `me` GET-es. A jövőbeli `SignupRequest`/`PasswordResetRequest` ide kerül, amikor megjönnek az endpointok.
- **OpenAPI generálás** — M4.b.2 hozza a `zircote/swagger-php`-t. A DTO-k attribútum-megjelölései viszont már az OpenAPI-ra optimalizáltak.
- **Pagination konvenció** — M4.b.3.
- **Rate limit middleware** — M4.b.4.

## M4.b.2 — OpenAPI + Swagger UI

**Cél**: a backend self-documenting — minden `/api/v1/*` endpoint a saját kódja mellett deklarálja a kontraktusát `OA\*` attribútumokkal, a `zircote/swagger-php` ezt scanneli, és a `/api/v1/docs.json` (JSON spec) + `/api/v1/docs` (Swagger UI) endpointok kiszolgálják. A React kliens majd `openapi-typescript`-tel generál típusokat a `docs.json`-ból (M6).

### Új fájlok

#### OpenAPI infrastruktúra
- [src/Framework/OpenApi/OpenApiInfo.php](../src/Framework/OpenApi/OpenApiInfo.php) — üres osztály a top-level `#[OA\OpenApi]` + `#[OA\Info]` + `#[OA\Server]` + `#[OA\SecurityScheme]` (Bearer JWT) attribútumokhoz. Külön osztály, hogy a controllerek és DTO-k mentesek maradjanak a root-meta zajtól.
- [src/Framework/OpenApi/OpenApiGenerator.php](../src/Framework/OpenApi/OpenApiGenerator.php) — wrapper a `zircote/swagger-php` `Generator::scan()`-jén. Konfigurálható scan-utak (`forSource()` factory az alapértelmezett `Framework/OpenApi`, `Framework/Controllers`, `Application/Controllers`, `Application/Dto` listát adja). Cache-fájl támogatás: ha létezik a `var/cache/openapi.json`, abból olvas; egyébként scan futási időben.

#### Controllers
- [src/Framework/Controllers/Api/V1/DocsController.php](../src/Framework/Controllers/Api/V1/DocsController.php) — két endpoint:
  - `GET /api/v1/docs.json` — a `OpenApiGenerator::toJson()` outputját szolgálja `application/json`-ként, `Cache-Control: no-store`.
  - `GET /api/v1/docs` — Swagger UI HTML, az `unpkg.com/swagger-ui-dist@5` bundle-ből betöltve. Csak akkor érhető el, ha `APP_ENV != production` (egyébként 404 problem+json).

#### CLI
- [src/Framework/Console/OpenApiDumpCommand.php](../src/Framework/Console/OpenApiDumpCommand.php) — `bin/console openapi:dump` precompile-ja a JSON-t `var/cache/openapi.json`-be (`--clear` opció a fájl eltávolításához). Production deploy-flow: `bin/console route:cache && bin/console openapi:dump`.
- [src/bin/console](../src/bin/console) — új parancs regisztrálva a runner-ben.

### Módosítások (OA markup)

- [src/composer.json](../src/composer.json) + composer.lock — új dep `zircote/swagger-php: ^4.10` (tranzitív: `symfony/yaml`, `symfony/finder`).
- [src/Application/Dto/LoginRequest.php](../src/Application/Dto/LoginRequest.php) — `#[OA\Schema(schema: 'LoginRequest', required: [...])]` osztály-szinten, `#[OA\Property(...)]` minden property mellett. A `Symfony\Assert\*` és `OA\Property` jelölések kiegészítik egymást, ugyanannak az invariánsnak a két nyelven (futási validáció + dokumentáció).
- [src/Application/Dto/VerifyTwoFactorRequest.php](../src/Application/Dto/VerifyTwoFactorRequest.php) — ugyanaz a minta.
- [src/Framework/Controllers/Api/V1/AuthController.php](../src/Framework/Controllers/Api/V1/AuthController.php) — `#[OA\Post]` / `#[OA\Get]` minden auth endpointra (`login`, `verifyTwoFactor`, `refresh`, `logout`, `me`), tags + responses + requestBody-ref a DTO-kra. A `me` endpoint security `bearerAuth`, a többi `security: []` (a public auth flow lépései).

### Mit *nem* tartalmaz ez a PR

- **openapi-typescript generálás a kliens számára** — M6-ban a `examples/react-spa/` `package.json` script-jeként landol (`openapi-typescript /api/v1/docs.json -o src/api/generated.ts`).
- **DTO-szintű OA `description` mezők finomítása** — most csak a vázat tartalmazza; a részletes leírások az endpointok érése során íródnak.
- **Response schemák** — a 200 válaszok body-stuktúrája nincs deklarálva (`AccessTokenResponse`, `MeResponse` DTO-k még nem léteznek). M4.b.3 (`{data, meta}` envelope) után jönnek, hogy a pagination konvencióval konzisztens DTO-k szülessenek.
