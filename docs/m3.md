# M3.a — Drop-in SPA webroot + `.htaccess` SPA fallback + `APP_SPA_MODE`

**Cél**: a backend egyetlen origin-en tudjon kiszolgálni egy buildelt SPA-t (`embedded` mód), és ugyanaz a kódbázis működjön egy külön origin-en futó SPA-val is (`separate` mód). M3.a a webroot-konvenciót, az Apache `.htaccess` rewrite-ot, a Nginx vhost mintát és a PHP-szintű `APP_SPA_MODE` enumot szállítja.

## Új fájlok

- [src/html/app/.gitkeep](../src/html/app/.gitkeep) — drop-in SPA webroot helye. CI / dev `cp -r dist/* src/html/app/`-pel tölti.
- [src/Framework/SpaMode.php](../src/Framework/SpaMode.php) — `enum SpaMode: string` (`SEPARATE`, `EMBEDDED`, `BOTH`). `SpaMode::current()` env-ből, `servesSpa()` / `requiresCors()` döntés-segéd metódusok.
- [docker/nginx/default.conf.example](../docker/nginx/default.conf.example) — production Nginx vhost minta. `try_files` SPA history fallback, fastcgi PHP-FPM upstream, env-passthrough `APP_SPA_MODE` és `APP_ENV` változókra.
- [src/tests/Framework/SpaModeTest.php](../src/tests/Framework/SpaModeTest.php) — 6 teszt: default `SEPARATE`, recognized modes, case-insensitivity, `servesSpa`/`requiresCors` truth-table, `current()` reads env.

## Módosítások

- [src/html/.htaccess](../src/html/.htaccess) — teljes újraírás. Hat szabály:
  1. `/api/*` → `index.php` (a backend kapja).
  2. `/healthz`, `/readyz` → `index.php` (rendszer endpointok — M5 fogja implementálni).
  3. `/app/*` alatt **létező** fájl → direktben szolgálva.
  4. `/app/*` alatt **nem létező** fájl + létező `app/index.html` → SPA history fallback.
  5. Bármely más path + létező `app/index.html` → SPA fallback (embedded mód a `/`-en is a SPA-t adja).
  6. Egyéb → `index.php` (separate mód: a backend dönt 404 vs route hit).
- [src/.env.example](../src/.env.example) — új `APP_ENV` és `APP_SPA_MODE` mezők, kommenttel.
- [.gitignore](../.gitignore) — `/src/html/app/*` kizárva, kivéve a `.gitkeep`. Így a mappa szerkezete verzionált, a build-output nem.

## Üzemi módok

| Mód | Mit szolgál a backend root-ja | CORS | Tipikus deploy |
|---|---|---|---|
| `separate` | csak `/api/*` (nem-API → backend 404) | allow-list aktív | SPA Vite dev-en vagy külön CDN-en |
| `embedded` | `/api/*` + `/app/*` + `/` → SPA index | off (same origin) | Egyetlen Docker image (M5) |
| `both` | mindkettő egyidejűleg | aktív | Lokális fejlesztés |

A `.htaccess` és Nginx config **fájl-jelenlét** alapján dönt (létezik-e `app/index.html`), így ugyanaz a webroot mindkét módban használható. Az `APP_SPA_MODE` env változó a PHP-réteg (CORS, esetleges info endpoint) számára informatív.

## Verifikáció

- **PHPUnit**: 77/77 zöld (71 → 77, +6 új SpaMode teszt).
- **PHPStan level 1**: **14 hiba** — változatlan; 0 új hiba az új kódból.
- **`gitnexus_detect_changes`**: 4 fájl módosulva, 0 érintett szimbólum, 0 affected process, risk=low — additív bővítés.
- **Manuális smoke teszt** (Apache):
  - `app/index.html` nélkül: `curl http://localhost/foo` → backend 404 (separate mód).
  - `echo "<html>ok</html>" > src/html/app/index.html`, `curl http://localhost/foo` → SPA index (embedded mód).
  - `curl http://localhost/api/v1/auth/me` → mindkét módban a backendhez megy.

## Biztonsági / üzemeltetési jegyzetek

- A SPA build content-hash-elt assetjei `Cache-Control: public, immutable; max-age=7d`-vel mehetnek (Nginx példában szerepel). Az `index.html`-re viszont `no-cache` ajánlott (M5).
- A `.htaccess` `Options -MultiViews` direktívája megelőzi, hogy az Apache "occasionally" más kiterjesztést próbáljon (pl. `/users` → `users.php`).
- `app/index.html` jelenléte = embedded mód aktív. A CI deploy lépésnek a SPA build végén kell ezt a fájlt elhelyeznie — addig a backend separate módban viselkedik.
- Az `APP_SPA_MODE` env változót a PHP-FPM-en keresztül kell átadni (Nginx példában `fastcgi_param`). Az Apache mod_php beépített konfigjába `SetEnv APP_SPA_MODE embedded` formában tehető.

# M3.b — Route cache + method-aware 405/404 + reflection-alapú ClassExploder

**Cél**: a routing rétegnek három látható javulása legyen — (1) production-időben ne kelljen reflection-szel scannelni minden requesten, (2) a Dispatcher tudjon különbséget tenni 405 és 404 között, (3) a `ClassExploder` ne regexszel keressen `#[Path]` attribútumokat. A munka egyúttal javította, hogy a `Framework\Controllers\Api\V1\AuthController` ténylegesen routolható legyen a live appben — a régi regex-implementáció nem ismerte fel azon controllereket, ahol nincs class-szintű `#[Path]`.

## Új fájlok

- [src/Framework/Routing/MatchResult.php](../src/Framework/Routing/MatchResult.php) — immutable value object: `found(array $params)`, `methodNotAllowed(list<string> $allowed)`, `notFound()`.
- [src/Framework/Routing/RouteCache.php](../src/Framework/Routing/RouteCache.php) — PHP-fájl alapú cache `var/cache/routes.php`-ben. Verzióelt; atomic write (temp + rename); `load()` null-t ad, ha a fájl hiányzik vagy elromlott.
- [src/Framework/Console/RouteCacheCommand.php](../src/Framework/Console/RouteCacheCommand.php) — `bin/console route:cache` (build) és `route:cache --clear` (delete).
- [src/tests/Framework/ClassExploderTest.php](../src/tests/Framework/ClassExploderTest.php), [Routing/MatchResultTest.php](../src/tests/Framework/Routing/MatchResultTest.php), [Routing/StandardRouterImplTest.php](../src/tests/Framework/Routing/StandardRouterImplTest.php), [Routing/RouteCacheTest.php](../src/tests/Framework/Routing/RouteCacheTest.php) — 16 új teszt.

## Módosítások

- [src/Framework/ClassExploder.php](../src/Framework/ClassExploder.php) — teljes újraírás. A regex-alapú scan helyett Composer autoloader `getClassMap()` + `getPrefixesPsr4()`. Production-optimizált (`composer install -o`) class-map-ből instant; dev-ben a PSR-4 base-dir rekurzívan walked. **Új viselkedés**: class-szintű `#[Path]` hiányában (de method-szintű létezésekor) `/__class__/{FQCN}` sentinel kulcs.
- [src/Framework/Routing/Router.php](../src/Framework/Routing/Router.php) — szignatúra változott: `match(string $url, ?string $method = null): MatchResult`.
- [src/Framework/Routing/StandardRouterImpl.php](../src/Framework/Routing/StandardRouterImpl.php):
  - Konstruktor új opciós paramétere `?array $cachedRoutes`. Ha jelen, route-tábla közvetlenül abból.
  - `discoverRoutes(): array` — public static; `RouteCacheCommand` is használja.
  - `match()` MatchResult-tot ad, method-aware (405 vs 404).
  - `getParams()` eltávolítva — a MatchResult immutable.
- [src/Framework/Dispatcher.php](../src/Framework/Dispatcher.php) — `handleRequest()` MatchResult-tal: `isMethodNotAllowed()` → 405, `isNotFound()` → 404, `isFound()` → tovább.
- [src/Framework/Bootstrap.php](../src/Framework/Bootstrap.php) — `RouteCache->load()` próbálkozik; cache-hit esetén nincs reflection-scan.
- [src/bin/console](../src/bin/console) — új `route:cache` parancs.
- [.gitignore](../.gitignore) — `/src/var/` ignored.

## CLI használat

```bash
bin/console route:cache         # build (deploy step)
bin/console route:cache --clear # invalidate
```

Production CI:
```bash
composer install --no-dev --optimize-autoloader
bin/console route:cache
```

Dev-ben javasolt **nem** generálni — minden mentés után friss reflection-scan fut.

## Verifikáció

- **PHPUnit**: 77 → **93/93 zöld** (+16 új teszt).
- **PHPStan level 1**: **14 hiba** — változatlan, 0 új.
- **`gitnexus_detect_changes`**: 9 fájl, 23 érintett szimbólum, 5 affected process (HandleRequest változatok), risk=medium. Várt: `Dispatcher::handleRequest` szignatúra-belseje változott.
- **Smoke teszt**: `bin/console route:cache` 5 route-ot ír ki (`/api/v1/auth/{login,refresh,logout,me,2fa/verify}`) — confirms a teljes Auth-flow most már a live dispatcher-en is routolható.

## Breaking changes

- `Router::match()` szignatúra (`array | bool` → `MatchResult`). Egy belső impl + egy belső callsite frissítve. `RequireAuthIntegrationTest` mockoló Router-t használ — BC-szempontból OK.

# M3.c — PSR-11 container csere (php-di)

**Cél**: a saját `Framework\Container` autowire-DI-osztály leváltása a [`php-di/php-di`](https://php-di.org/) (PSR-11 kompatibilis) ellenőrzött könyvtárral. A migráció pontszerűen aprólékos — `Container` csak két helyen volt használva (Bootstrap + Dispatcher) —, így a `Dispatcher` szerződését `Psr\Container\ContainerInterface`-re vékonyítjuk.

## Új fájlok

- [src/Framework/ContainerFactory.php](../src/Framework/ContainerFactory.php) — `static build(?string $compilationDir = null): ContainerInterface`. Autowiring be, attribute-DI ki. Opcionális production compile-cache (`enableCompilation`) az `APP_DI_COMPILE` env változó alatt.
- [src/tests/Framework/ContainerFactoryTest.php](../src/tests/Framework/ContainerFactoryTest.php) — 5 teszt: PSR-11 contract, autowire Response, paraméter nélküli osztály resolution, konstruktor-paraméter autowire, `has()`.

## Módosítások

- [src/composer.json](../src/composer.json) + composer.lock — új dep `php-di/php-di: ^7.1` (tranzitívan `psr/container: ^2.0`, `php-di/invoker`, `laravel/serializable-closure`).
- [src/Framework/Dispatcher.php](../src/Framework/Dispatcher.php) — konstruktor szignatúrája: `Container $container` → `ContainerInterface $container` (PSR-11). A `$container->get(Response::class)` hívás változatlan.
- [src/Framework/Bootstrap.php](../src/Framework/Bootstrap.php) — `new Container()` → `ContainerFactory::build($compilationDir)`. `APP_DI_COMPILE=1` env változó kapcsolja a production compile-cache-t a `var/cache/di/` mappába.
- [src/tests/Framework/Auth/RequireAuthIntegrationTest.php](../src/tests/Framework/Auth/RequireAuthIntegrationTest.php) — `new \Framework\Container()` → `$this->createMock(\Psr\Container\ContainerInterface::class)`.

## Törölt fájlok

- `src/Framework/Container.php` — a saját autowire impl. A `php-di` minden funkcióját lefedi.
- `src/tests/Framework/ContainerTest.php` — a saját Container-hez kötött tesztek. Helyettesíti a `ContainerFactoryTest`.

## Verifikáció

- **PHPUnit**: 93/93 zöld — ugyanannyi mint M3.b után (régi 5 `ContainerTest` helyett 5 új `ContainerFactoryTest`).
- **PHPStan level 1**: **14 hiba** — változatlan, 0 új.
- **`gitnexus_detect_changes`**: 7 fájl, 8 érintett szimbólum (Dispatcher konstruktor + a teszt), 0 affected process, risk=low.

## Compile-cache (production)

```bash
composer install --no-dev --optimize-autoloader
APP_DI_COMPILE=1 php -r "require 'vendor/autoload.php'; Framework\ContainerFactory::build('var/cache/di');"
```

A `var/cache/di/` mappának írhatónak kell lennie a futtató user számára. A `.gitignore` `/src/var/` szabálya már fedi.

## Mit *nem* tartalmaz ez a PR

- **Controller resolve a containerből** — jelenleg a `Dispatcher` még `new $controller($params)`-szel példányosít, mert a controllerek route-params-szal jönnek létre. A constructor-injection mintára való átállás külön PR (M3.d candidate).
- **Attribute-DI (`useAttributes(true)`)** — jelenleg nincs olyan service, ami igényelné.
- **Per-call (non-shared) Response** — a `php-di` default shared. PHP-FPM-ben (egy request = egy container) nem okoz gondot. Long-running worker setupokhoz (RoadRunner) request-scope reset majd egy követő PR-ben.

## Breaking changes

- `Framework\Container` osztály törölve. Külső kód, amely importálta, törik. **Pótlás**: `Psr\Container\ContainerInterface` (PSR-11), a `Framework\ContainerFactory::build()` által visszaadott `DI\Container` példánnyal.
