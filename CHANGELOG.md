# Changelog

All notable changes to Antarctic are documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project adheres to [Semantic Versioning](https://semver.org/).

## [1.0.0] — 2026-05-25

The first stable release. Antarctic is now a SPA-native, JWT-secured PHP 8.2 backend framework with a production-ready HTTP layer, observability stack, and Docker deployment.

### HTTP layer

- **PSR-7 / PSR-15 pipeline** with `Framework\Http\MiddlewarePipeline`, `HttpAdapter`, and `LegacyDispatcherMiddleware` adapter wiring controllers into the PSR-15 chain.
- **Attribute-based routing** (`#[Path]`) with method-aware 404/405 resolution (`MatchResult`), reflection-driven `ClassExploder`, and an opt-in production route cache (`bin/console route:cache`).
- **CORS middleware** with config-driven allow-list, preflight short-circuiting, and credential support.
- **Error boundary middleware** rendering RFC 7807 `application/problem+json` responses; 5xx exceptions logged with full context, 4xx treated as expected client errors.
- **Content negotiation** that forces JSON responses on every `/api/*` path regardless of `Accept`.
- **Validated request DTOs** via `Framework\Validation\RequestHydrator` + `symfony/validator`; validation failures map to 422 problem+json with structured `errors`.
- **Pagination convention** with `PaginationParams`, `SortField`, and the generic `Page<T>` envelope.
- **Rate-limit middleware** (PSR-15) with in-memory and Redis stores; both `predis/predis` and `phpredis` (ext-redis) adapters ship in-tree, atomic INCR+EXPIRE via Lua.
- **Security headers middleware** (CSP, HSTS, X-Frame-Options, Referrer-Policy, Permissions-Policy) decorating every response including 5xx errors.
- **HTTPS redirect middleware** (opt-in via `APP_FORCE_HTTPS`), proxy-aware via `APP_TRUST_PROXY`, with healthcheck path exclusions for k8s probes.
- **Trace ID middleware** propagating `X-Request-Id` end-to-end into Monolog log records (`extra.trace_id`).

### Authentication

- **RS256 JWT** access tokens (`lcobucci/jwt`) with `iss` / `aud` / `jti` / clock-skew enforcement and explicit algorithm pinning against the alg-confusion attack.
- **Refresh token rotation** with reuse detection: a single replay revokes the entire `family_id` chain, forcing both legitimate and attacking clients to reauthenticate.
- **Refresh token cookie** uses the `__Host-` prefix (Secure, HttpOnly, SameSite=Strict, Path=/) with double-submit CSRF cookie on the dedicated refresh endpoint.
- **AuthMiddleware** parses Bearer tokens, populates an `AuthenticatedUser` request attribute, and never rejects on its own; the `#[RequireAuth]` and `#[RequireRole]` attributes drive policy at dispatch time.
- **Auth endpoints** under `/api/v1/auth/`: `login`, `refresh`, `logout`, `me`, and `2fa/verify`.
- **Two-factor authentication** challenge flow with per-user-per-method TOTP enrollment and verification.
- **`keys:generate` console command** producing a `0600`/`0644` RSA-4096 key pair under `var/keys/`.

### Container and dispatching

- **PSR-11 container** built on `php-di/php-di` with autowire, attribute-DI (`useAttributes(true)`), and opt-in compile cache (`APP_DI_COMPILE=1`).
- **Controller resolution through `FactoryInterface::make()`** — every controller receives its `Request`, `Response`, and route parameters via constructor injection; any additional dependencies autowire from the container. Each dispatch gets a fresh `Response` to avoid header bleed in long-running worker setups.

### Persistence

- **Doctrine migrations 3.7+** with driver-agnostic `Schema` API (sqlite/MariaDB/PostgreSQL).
- **Repository layer** — `UserRepository`, `TwoFactorRepository`, `RefreshTokenRepository` — using PDO injection via the container.
- **Dual-database support** (MariaDB and PostgreSQL) selected via `DATABASE` env, with separate docker build contexts under `docker/`.

### Observability

- **Structured JSON logging** via Monolog (`LoggerFactory::fromEnv()`), every record carrying the request trace ID.
- **Healthcheck endpoints**: `/api/v1/healthz` (liveness) and `/api/v1/readyz` (readiness, with database ping).
- **OpenAPI 3.1 spec** generated by `zircote/swagger-php` from `#[OA\*]` attributes; served at `/api/v1/docs.json`, with Swagger UI mounted at `/api/v1/docs` (dev-only by default). `bin/console openapi:dump` for build-time spec caching.

### SPA deployment

- **`APP_SPA_MODE` enum** (`separate` / `embedded` / `both`) drives CORS and routing decisions in the PHP layer.
- **Drop-in webroot** (`src/html/app/`) with `.htaccess` history fallback for embedded SPA deploys; production Nginx vhost example for the same pattern.
- **React + Vite + TypeScript example** under [`examples/react-spa/`](examples/react-spa/) demonstrating the canonical access-in-memory + refresh-cookie + CSRF double-submit flow, with `ProtectedRoute` guard waiting on `/me`.

### Production Docker stack

- **Multi-stage `docker/php-fpm/Dockerfile`** (vendor → build → runtime); build stage pre-warms the route cache and dumps the OpenAPI spec, runtime is a lean `php:8.2-fpm-alpine`.
- **`docker-compose.prod.yml`** wiring PHP-FPM, Nginx, PostgreSQL 16, and Redis 7 with healthchecks and production env defaults (`APP_ENV=production`, `APP_DI_COMPILE=1`, `APP_FORCE_HTTPS=1`, `APP_RATE_LIMIT_BACKEND=redis`, …).

### Tooling

- **PHPUnit 11** test suite (226 tests, 532 assertions).
- **PHPStan level 1** static analysis gating CI.
- **GitHub Actions CI** running composer validate, lint, PHPStan, and PHPUnit on every push and PR to `main`.
